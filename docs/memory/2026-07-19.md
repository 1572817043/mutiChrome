## 后续注意

- 布局同步 V0 仍依赖 macOS 辅助功能权限，但窗口控制已迁移到 MultiChrome 进程内的原生 Accessibility API，不再依赖 `/usr/bin/osascript`。
- 当前只同步首个窗口的位置和大小；如果主账号窗口在外接屏或屏幕外，目标窗口也会被设置到同一坐标，后续可增加可见区域校验。
- 读回验证只能证明 macOS 返回的首窗坐标接近目标坐标；如果窗口在其它桌面空间、全屏空间、被系统动画延迟或被 Chrome 后续改回，仍可能需要用户肉眼复测。
- 这不是实时窗口同步，也不是群控；下一步如果继续做，应先处理窗口选择、最小化/全屏提示和多屏边界。
- 已运行账号再次点击卡片时，如果当前页本身已经是 `chrome://newtab/`，Chrome 可能视觉上只是聚焦现有新标签而不是再增加一个空白标签；如果后续强需求是“每次点击必定多出一个新标签”，可能要另做辅助功能快捷键或浏览器调试协议方案。
- 运行状态已做轻量前端轮询；后续除非遇到明显性能问题，否则不用急着做 Rust watcher。目录大小统计如果需要，建议做左侧独立统计模块，不回到账号卡片常驻展示。
