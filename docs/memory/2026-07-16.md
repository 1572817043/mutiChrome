## 已知限制

- 自动验证能确认 helper 进程、Chrome profile 参数、reopen 不重复开进程；Dock 图标视觉表现和聚焦手感仍需要用户肉眼看。
- 通过 AppleScript / System Events 聚焦具体 Chrome 主进程可能受系统辅助功能权限影响；脚本里已做失败容忍。
- helper 目前仍是实验脚本生成能力，还没有接入 MultiChrome 主应用 UI。
- 外部 Dock 图标区分路线已暂停，不纳入当前 MVP。
- 健康检查的一键修复目前只做低风险创建类问题；损坏索引恢复、重复 ID 修复仍需要后续设计人工确认流程。
- 孤儿目录登记目前是一条条手动确认，暂未做批量登记和登记前改名。
- 常用网址目前只有 URL 本身，暂未做备注、分组或排序。
- 项目网址列表目前支持新增、删除、编辑、批量导入、复制和按钮排序；暂未做拖拽排序。
- UI 当前仍是偏轻量启动器风格；后续要继续向更成熟的生产力管理台打磨，但主视图不回到大表格。
- 队列间隔目前暂未持久化为用户偏好。
- 账号平台资料库第一版已完成，但只保存平台、登录网址、用户名和备注。
- 密码字段需要先设计安全存储方案，不能直接明文写入 `profiles.json`。
- 网页自动填入账号密码暂不做。
- 完整 profile 文件夹备份、批量清理缓存还未做。

## 下一步建议

- 下一步继续核心功能流畅度：账号批量导入已有 profile、账号平台资料库搜索/排序/常用平台模板、项目和账号之间的联动入口、完整 profile 文件夹备份、批量删除、孤儿目录登记后的批量编辑、常用网址备注/分组。
- 密码和自动填入分阶段谨慎处理，先不进入当前基础功能阶段。
- AI 助手和窗口同步已记录为后期路线，等基础功能通过实际使用打磨后再单独设计。
- 外部 Dock 图标区分后续除非重新明确需要，否则不继续推进。
