# 2026-07-15 工作日志

## 本轮完成

- 修复账号启动后强制打开 `about:blank` 的问题；Chrome 启动参数现在只保留 `--user-data-dir=/path` 和 `--no-first-run`，不再传起始网址。
- 实现 V0.4 第一段基础功能：账号颜色标识、编辑弹窗修改颜色、标准/紧凑视图切换。
- 实现账号多选能力：单卡选择、全选当前、取消选择。
- 实现基础批量操作：批量标记正常、批量标记待检查、批量归档、批量追加标签。
- 新增 `accentColor` 元数据字段，写入 `profiles.json`，跟随配置根目录迁移；老账号没有该字段时按账号编号显示默认色。
- Rust 端 `StoredProfile` 增加可选 `accent_color` 字段，避免桌面端读写真实配置时丢失颜色。
- 更新 `docs/progress.md` 和 `docs/project-overview.md`，记录 V0.4 状态、字段变更、验证结果和后续方向。
- 根据用户反馈，明确 App 内颜色不是主需求；真正要解决的是 Dock 或外部已打开图标如何区分不同账号。
- 默认颜色扩展到 12 个作为弱辅助，但颜色仍只作为列表扫视和分类，不作为 50 个账号的唯一识别方式。
- 优化中等宽度窗口下工具栏散开的问题，搜索区和筛选/全选/数量操作组分离。
- 增加当前会话内重复启动防护，同一账号已经启动后再次点击卡片不会重复打开新的 Chrome 窗口。
- 完成外部启动器第一轮技术实验：新增 `experiments/launcher-apps/generate-launcher-apps.mjs` 和对应测试。
- 实验脚本可生成独立 macOS `.app` 启动入口，例如 `.launcher-experiment/MC-account-001.app`、`.launcher-experiment/MC-account-002.app`。
- 每个实验启动器包含独立 `CFBundleIdentifier`、启动脚本和直接生成的 `.icns` 图标；图标使用颜色和号码角标区分账号。
- 桌面验证确认两个实验启动器分别能用 `account-001`、`account-002` 的 `--user-data-dir` 拉起 Chrome，且没有传 `about:blank`。
- 记录一个关键结论：shell `.app` 启动器能区分“启动入口”，但运行中的 Chrome 进程仍属于 `/Applications/Google Chrome.app`，所以 Dock 运行图标是否能变不能靠这一层解决。
- 调试中发现当前环境的 `iconutil` 对 iconset 转换不可靠，甚至对现有 `.icns` 反解出的 iconset 再转回也报 `Invalid Iconset`；实验脚本已改为直接写 `.icns` 二进制容器。

## 已知限制

- 主应用打包后未重新做完整人工点击验收；本轮只对实验启动器做了真实打开验证。
- 多选批量功能目前只覆盖状态和标签，暂未做批量删除、批量导入或数据备份。
- Dock 中多个 Chrome 图标仍然来自同一个 Chrome app，系统层面暂未区分。
- 简单启动同一个 `/Applications/Google Chrome.app` 无法改变 Dock 图标；需要后续实验独立 `.app` 启动器或窗口内 profile 标识方案。
- 独立 `.app` 启动器第一轮只解决“不同入口”，尚未解决“运行中的 Dock 图标和窗口归属”。

## 下一步建议

- 优先做数据备份/恢复和目录健康检查：检测缺失 profile、孤儿 profile、空目录、`profiles.json` 损坏或无法写入。
- 下一轮外部图标实验建议做保持运行的轻量 helper app：启动 Chrome 后自身不退出，后续点击 Dock helper 图标时聚焦对应 profile 窗口。
- 之后再做空间明细和安全清理缓存。
